# Sendoff

A private, sealed group keepsake for retirements, graduations, teachers at the end of the year,
colleagues moving on, coaches at the end of a season, and anyone leaving a team.

*Kudoboard is a bulletin board. Sendoff is a sealed envelope.*

|---|---|

| Subtitle | Graduation, Retirement, Moving |
| Bundle ID | `com.dahvio.sendoff` |
| Domain | `sendoffapp.com` |
| Stack | SwiftUI (iOS 17+), Supabase, Vite web |

## Run the iOS app (on the Mac)

```bash
brew install xcodegen
cd ios
cp Config/Local.xcconfig.example Config/Local.xcconfig   # team QNK434TFA6; supabase/setup.sh fills the keys
xcodegen generate
open Sendoff.xcodeproj
```

Without Supabase keys the app runs against `MockStore`, an in-memory store seeded with a
believable retirement Sendoff, so every screen including the reveal is demoable offline.
Run the `SendoffTests` scheme to check theme contrast, store rules and payment rules. The
scheme runs with `Sendoff.storekit`, so the paywall works in the simulator with test purchases.

## Run the web app

```bash
cd web/app && npm install && npm run dev     # http://localhost:5173
```

With no `.env.local` it runs on mock data. The landing page links to the three demo Sendoffs:
the reveal (`/s/maria-r/open?k=demo`), a sealed one with a countdown, the contribute form and
the printable QR card. `npm run build` typechecks and builds `dist/` for a static host with
SPA rewrites. `npm run e2e` runs the Playwright smoke test (reveal, countdown, contribute with
edit and photo, QR card) in headless Chromium. Details in `web/app/README.md`.

`web/prototype/` is the static design prototype the site grew out of; the colored dots switch
themes.

## Check the database rules without a Supabase project

```bash
supabase/tests/run.sh      # needs postgresql 16 binaries; starts a throwaway cluster
# on a Mac: brew install postgresql@16, then PGBIN=/opt/homebrew/opt/postgresql@16/bin supabase/tests/run.sh
```

Applies the migrations on plain Postgres (with stubs for the `auth` and `storage` schemas) and
runs `supabase/tests/rules_test.sql`: contributors see only their own entry, forged inserts are
refused, the recipient key reveals nothing before the open, Free stops at 10, a credit is spent
once, review mode never leaks a pending entry. CI runs it on every push.

## Set up the backend

```bash
brew install supabase/tap/supabase
supabase login                       # opens the browser
supabase/setup.sh <project-ref>      # from the dashboard URL: supabase.com/dashboard/project/<ref>
```

Create the project in the dashboard first (any region; note the database password, linking asks
for it). The script is safe to re-run. It links the project, applies the migrations, pushes the
auth settings in `supabase/config.toml` (anonymous sign-ins on, `https://sendoffapp.com` as the
site URL), deploys `sign-media` and `process-media`, stores the project URL and service role key
in Vault for the `media` trigger (`0004_media_webhook.sql`, which replaces the dashboard
webhook), and writes the URL and anon key into `ios/Config/Local.xcconfig` and
`web/app/.env.local`.

Stock music: put the four licensed tracks in `supabase/stock-music/` (gitignored) named by track
id, `warm_piano.m4a`, `bright_strings.m4a`, `reflective_guitar.m4a`, `triumphant_brass.m4a`, and
run the script again; it uploads them to the public `stock-music` bucket.

Apple Music (Plus): turn on **MusicKit** for the `com.dahvio.sendoff` App ID. For the 30-second
previews the website and non-subscribers hear, create a Media ID with MusicKit and a key with
**Media Services**, then give the `apple-music` function its secrets. Run it from the folder
holding the `.p8`, which Apple lets you download once:

```bash
supabase secrets set --project-ref <ref> MUSICKIT_TEAM_ID=QNK434TFA6 MUSICKIT_KEY_ID=<key id> MUSICKIT_PRIVATE_KEY="$(cat AuthKey_<key id>.p8)"
```

## The website

sendoffapp.com is served by Cloudflare: the Worker `sendoffapp` (static assets only, no code;
`web/app/wrangler.jsonc`) on the Cloudflare account rayrothwell1@gmail.com, attached to the bare
domain as a custom domain. The domain is registered at Namecheap with its nameservers on
Cloudflare. `www` is a proxied `CNAME` to the bare domain, and a redirect rule on the zone sends
it to the bare domain, which must serve `/.well-known/apple-app-site-association` itself (team
`QNK434TFA6`). Mail for the domain, including support@sendoffapp.com, is hosted by Purelymail;
its MX, SPF, DKIM and DMARC records sit in the same Cloudflare zone and are DNS only, never proxied.

Deploy after `npx wrangler login` (it builds first):

```bash
cd web/app && npm run deploy
```

A build without Supabase keys is the public landing, `/privacy` and `/support`; Sendoff links
explain that they start working at launch. Once `supabase/setup.sh` has written
`web/app/.env.local`, build and deploy again and the links go live. Demo data only appears in
`npm run dev`, the smoke test (`vite build --mode demo`) and with `?mock` in a URL.
